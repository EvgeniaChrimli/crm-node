# Tasks API

Backend на Express + TypeScript + PostgreSQL. Ниже — пошаговая инструкция, как развернуть проект локально с нуля.

## Стек

- Node.js + TypeScript
- Express 5
- PostgreSQL (через `pg` и `node-pg-migrate`)
- JWT-аутентификация (access/refresh токены в httpOnly-куках)

## Необходимое окружение

Перед началом убедитесь, что на компьютере установлено:

- **Node.js** версии 20 или выше (и npm)
- **PostgreSQL** версии 14+ (установлен и запущен локально, либо доступен удалённо)
- **Git**

Проверить версии:

```bash
node -v
npm -v
psql --version
```

## 1. Клонирование проекта

```bash
git clone <ссылка-на-репозиторий>
cd tasks
```

## 2. Установка зависимостей

```bash
npm install
```

## 3. Настройка PostgreSQL

Создайте базу данных, которую будет использовать проект (имя — на ваше усмотрение, например `practice`):

```bash
psql -U postgres -c "CREATE DATABASE practice;"
```

Если для пользователя `postgres` задан пароль — используйте его при подключении. При необходимости создайте отдельного пользователя БД.

## 4. Настройка переменных окружения

Скопируйте пример `.env` и заполните своими значениями:

```bash
cp .env.example .env
```

Переменные, которые нужно указать в `.env`:

| Переменная | Назначение |
| --- | --- |
| `DATABASE_URL` | Строка подключения к БД (используется миграциями) |
| `PORT` | Порт, на котором поднимется сервер (по умолчанию `5000`) |
| `NODE_ENV` | `development` / `production` |
| `CORS_ORIGIN` | Адрес фронтенда, которому разрешён доступ (например `http://localhost:5173`) |
| `DB_HOST`, `DB_PORT`, `DB_USER`, `DB_PASSWORD`, `DB_NAME` | Параметры подключения к PostgreSQL для приложения |
| `JWT_ACCESS_SECRET`, `JWT_REFRESH_SECRET` | Секреты для подписи JWT-токенов (задайте свои произвольные строки) |

`DATABASE_URL` и `DB_*` должны указывать на одну и ту же базу.

## 5. Применение миграций

Миграции лежат в папке `migrations/` и накатываются через `node-pg-migrate`.

При первом разворачивании проекта нужно накатить все существующие миграции, чтобы создать таблицы в БД:

```bash
npm run migrate:up
```

В дальнейшем заново выполнять `migrate:up` нужно **только тогда, когда в проекте появились новые миграции** — то есть после того, как вы или кто-то из команды изменил структуру таблиц (добавил колонку, новую таблицу и т.д.) и закоммитил новый файл в `migrations/`. Например, после `git pull`, если в нём пришли новые файлы миграций.

Просто так на каждый запуск сервера гонять миграции не требуется — если новых файлов миграций нет, `migrate:up` ничего не сделает. Учтите, что скрипт `predev` уже делает это автоматически перед `npm run dev`, так что вручную запускать `migrate:up` обычно нужно только сразу после клонирования проекта или после подтягивания чужих изменений с новыми миграциями.

Откатить последнюю миграцию (если нужно):

```bash
npm run migrate:down
```

Создать новую миграцию:

```bash
npm run migrate:create <название-миграции>
```

> Миграции также автоматически применяются перед стартом дев-сервера (см. скрипт `predev`).

## 6. Создание первого администратора

Пользователи не регистрируются свободно — эндпоинт `/auth/register` доступен только администратору. Поэтому первого админа нужно создать через CLI-скрипт:

```bash
npm run create:admin
```

Скрипт запросит в консоли имя, email и пароль (не короче 8 символов) и создаст пользователя с ролью `ADMIN`.

## 7. Запуск сервера

Режим разработки (с автоперезапуском и авто-миграциями):

```bash
npm run dev
```

Сервер поднимется на `http://localhost:<PORT>` (по умолчанию `5000`).

Сборка и запуск production-версии:

```bash
npm run build
npm start
```

> ⚠️ Сервер нужно держать запущенным (`npm run dev`) каждый раз, когда вы хотите протестировать что-то на фронтенде — фронт обращается к этому API по адресу из `CORS_ORIGIN`/`PORT`, и без поднятого бэкенда запросы будут падать.

## 8. Тестирование ручек (API)

Тестировать эндпоинты можно в любом HTTP-клиенте, например:

- **Postman**
- **Insomnia**
- **Thunder Client** (расширение для VS Code)

Особенности:

- Авторизация построена на httpOnly-куках (access/refresh токены), поэтому в клиенте должна быть включена работа с куками (в Postman/Insomnia это по умолчанию так через встроенный cookie jar).
- Основной сценарий проверки: `POST /auth/login` → куки с токенами сохранятся автоматически → дальше можно вызывать защищённые ручки (например `GET /auth/me`).
- Роут `POST /auth/register` доступен только авторизованному администратору (нужно сначала залогиниться под админом, созданным через CLI).

## Структура основных роутов

| Путь | Модуль |
| --- | --- |
| `/auth` | логин, регистрация, refresh, logout, me |
| `/users` | пользователи |
| `/branches` | филиалы |
| `/contacts` | контакты |
| `/access` | доступы |
| `/meeting` | встречи |
| `/sse` | Server-Sent Events |

## Полезные npm-скрипты

| Команда | Что делает |
| --- | --- |
| `npm run dev` | запуск в режиме разработки (с авто-миграциями) |
| `npm run build` | сборка TypeScript в `dist/` |
| `npm start` | запуск собранного проекта |
| `npm run migrate:up` | применить миграции |
| `npm run migrate:down` | откатить последнюю миграцию |
| `npm run migrate:create` | создать новую миграцию |
| `npm run create:admin` | создать первого администратора через CLI |
